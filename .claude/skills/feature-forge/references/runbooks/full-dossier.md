# Full dossier review

Use when the human explicitly chooses the comprehensive pre-build review route.
Preserve the established brief, architecture, Plan, and Progress records.

Clarify the premise, users, alternatives, and open decisions. Write a detailed
brief using the [brief guidance](../../../brief/SKILL.md), then investigate the
system with the [architecture guidance](../../../architecture/SKILL.md). Write
the [Plan](../../../plan/SKILL.md), including its authoritative verification
table and implementation strategy. Use the [templates](../templates.md).

Use [product thinking](../product-thinking.md) for the initial reasoning and
[modular authoring](../document-authoring.md) to compose authoritative leaves.
Keep the [Progress and review record](../progress-and-handoffs.md) current.

Select useful reviewers by risk and uncertainty. Integrate findings into the
source and record dispositions. Compose all leaves and review history into a
comprehensive dossier. Obtain the consolidated human approval requested by this
route before building. Silence does not establish approval.

After that review, continue through TDD, independent verification, shipping,
landing, and cleanup using [verification and release](../verification-and-release.md).
Do not repeat the document review per slice or add per-release approval gates
beyond those the consuming project or human explicitly requires.
