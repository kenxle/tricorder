# Plan

Use the [templates](../feature-forge/references/templates.md) and
[contracts and slices](../feature-forge/references/contracts-and-slices.md).
Define coherent outcomes, source selection, dependencies, authority, uncertainty
rules, integration ownership, and safe landing. Own the single
requirement-to-acceptance/proof/owner/evidence table.

Include a short throughput checkpoint in the implementation strategy: blocking
prerequisites, independent workstreams, shared writable state, and the smallest
safe decomposition. Explain what applies; a single owner may be best. Update it
when the strategy changes and link Progress to it.

Choose testing review for uncertainties in variants, failures, seams, or evidence.
Keep documents and findings available for inspection. Continue to TDD without a
routine document approval gate; obtain consolidated approval only for the chosen
full review route or an actual project requirement. Every route follows
[verification and release](../feature-forge/references/verification-and-release.md).
